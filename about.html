What it is, in plain words

Every task a student completes on Math Academy is sent to Timeback as an event and stored there. That covers what students did. But several things Math Academy knows never reach Timeback: the course Math Academy is actually running the student in, the exact XP left, the course grade, the SAT score estimate, how much of the time on a task was attentive or productive, and the per-topic knowledge map.

This skill does two things. It explains Timeback's Math Academy data: every field, how it is born, the traps, and twelve worked recipes an agent can follow. And it keeps a nightly copy of Math Academy's own records, matched to Timeback students, so agents get the missing figures from one place, and Math Academy's API is called a few hundred times a night instead of thousands of times a day.

The documents

A dictionary (meaning of every field, 26 named traps, open questions) and an enablement (12 capabilities with step-by-step recipes). An agent reads the front page first; it points at both.

The store

Math Academy's record per student: true course and start date, progress, exact XP remaining, grade, SAT estimate, completion date, account state; per-task engaged and productive time; a nightly history; knowledge maps on request.

The feedback wire

Anyone can file a finding at POST /feedback. Tickets are public, mirrored to GitHub daily, and every one filed so far has been fixed or answered. See them.

The nightly cycle

3:00 am Central
Snapshot
Pull Math Academy's full student list (4 pages) and Timeback's Math Academy roster. Match them: first by the id stored last night, then by login, then one lookup per new student. Rewrite every student's current state. Append tonight's row to each student's history.
3:45 am Central
Activity
For every student who had a Math Academy result on each school day since the last pull, fetch Math Academy's per-task record with its three clocks. The newest already-pulled day is re-pulled to catch late rows; rows are keyed by task, so nothing duplicates.
On request
Knowledge map
The first time someone asks for a student's map, one live call fetches it; it is cached for seven days. A student missing from the store is looked up live once, then carried every night after.
Always
Health
The status page shows every snapshot ever loaded, the last activity run and a stale flag that turns on if a night is missed. Alarms email the owner on any failed or missing run.

What is refreshed how

DataEach nightGrows or replaces
Current state: one row per student (course, XP left, grade, seats, agreement)Rebuilt in full from tonight's pullreplaced a complete picture every night
History: one compact row per student per dateTonight's row addedappended never deleted; course changes and completion dates accumulate
Activity: one row per Math Academy task, with elapsed, engaged and productive timeEach unpulled school day, plus a re-pull of the newest oneappended by day, keyed by task so re-pulls overwrite
Knowledge mapsUntouchedon demand cached seven days per student per course

Cost to Math Academy per night: 4 bulk calls, one lookup per newly added student, and about one activity call per active student per day pulled; each night re-pulls the previous day as well, so a normal night is roughly 800 to 900 calls, and a catch-up night after a gap costs proportionally more (the first scheduled night pulled three days for 1,143 calls). Nothing is called during the school day except a first-time knowledge map or a missing student.

Who can read what

No key needed

  • The front page, both documents, the reference files
  • The status page: freshness, schedule, health, what the last runs cost
  • Math Academy's course id to name map (its public catalogue)

With the reader's own Timeback key

  • Counts: how many students per course agree, disagree, never started, with test accounts split out
  • A student's Math Academy record, history, activity and knowledge map
  • A course's student list with Math Academy's figures per student
  • A course's engagement totals for one day

The skill replays the reader's token against Timeback and serves a student only if Timeback confirms that token can read them. The skill issues no keys and holds none for readers.

Never

  • No student value in any document or reference file
  • No names or logins to anyone without a token; a ?minimal=1 view drops them even for readers who have one
  • No figures read off the wire in the documents, only the queries that measure them

The twelve questions it answers

#Question a guide or lead asksWhere the answer comes from
1What did this student do on Math Academy this week?Timeback results, task by task, with type, topic, XP and accuracy
2How many minutes and XP per day?Timeback's daily rollups (engaged minutes)
3What course is she in and how far along?The store first (exact figures, dated), Timeback's newest result for today's percent
4Who has gone quiet in this course?Roster minus the estate's results, then the store says why (moved on, not started, wrong course, no record)
5Who finished, and were they moved on?Results first (the platform deletes the finished seat), confirmed by Math Academy's completion date
6Where is he struggling, and did he recover?Not-credited tasks by topic, latest attempt decides
7Is anyone in the wrong Timeback course?The store's course list, definitively; a weak Timeback-only heuristic as fallback
8How much Math Academy happened across the school yesterday?Every result of the school day, attributed to the course it was filed under
9Tell me this student's whole Math Academy storyEvery seat, every event under it, gaps, where 100 was reached
10What are Math Academy's own figures for this student?The store: true course, exact XP left, grade, SAT estimate, agreement with the seat
11Was he really working? Elapsed vs engaged vs productiveThe store's activity rows; Timeback holds only the engaged clock

Things the documents say plainly

  • The course an event is filed under is Timeback's seat, not Math Academy's course. If the seat is wrong, every event is filed wrong and no field says so. The store's agreement check is the only definitive answer.
  • A Timeback "100 percent" is not "finished". It is rounded, it can dip back, and Math Academy marks a course complete at the student's last lesson, sometimes months later.
  • Timeback's Math Academy minutes are engaged minutes, not wall time. Idle time on an open tab is already excluded; only the store shows it.
  • The Timeback-only XP estimate is a rough fallback that has run from 64 percent too high to 67 percent too low against the exact figure (the dictionary keeps the one current band). The store has the exact figure.
  • Students leave Math Academy on purpose. After finishing, progression gives them other math: TEKS Math, hole-filling, Math Raiders, supplements. That is never a flag.
  • The store began on 17 September 2026. Nightly history builds from there. Per-task activity is being backfilled from 1 July 2025 for every student who ever held a seat (a batch that runs over several hours; the status page shows how far it has got), and any student the batch has not reached is backfilled the first time someone asks for their activity.
  • Test accounts fill rosters (about a third of seats estate-wide; by course anywhere from none to nearly all, the five big grade courses running a fifth to two fifths; some carry no flag and are recognised by a naming pattern or a test campus, in the store, never by a reader) and barely appear in activity. Every count here is shown with them split out.

Testing

More than twenty independent cold-agent runs on 16 and 17 September 2026, each starting from the front page with a read-only Timeback key and no other knowledge, answered real guide questions and tried to break the skill. About 150 findings, every defect they found was fixed the same day and recorded as a closed ticket on the feedback wire (the open tickets there are the documented open questions). An adversarial reviewer verified every hash pin, that no student value reaches anyone without a token, and that the login gate leaks nothing. Contract predicates are re-checked on every deploy.
